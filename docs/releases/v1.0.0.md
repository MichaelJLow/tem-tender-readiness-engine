## What this release can do

The engine evaluates a synthetic business-energy tender before a mocked
downstream pricing handoff. Deterministic TypeScript rules own the final
route. The model may extract evidence from notes and already-extracted document
text; it cannot approve a tender, fill missing structured fields, or call
pricing.

Business routes:

- `READY_FOR_PRICING` — required information is present, consistent, and safe to hand downstream
- `NEEDS_INFORMATION` — required information is missing and can be requested clearly
- `HUMAN_REVIEW` — information is conflicting, ambiguous, or unsafe to resolve automatically
- `DUPLICATE` — the tender appears to have already been submitted

Technical status (`RECEIVED` / `PROCESSING` / `COMPLETED` / `FAILED`) stays
separate. Only a final `READY_FOR_PRICING` route may invoke the API-owned mock
pricing gateway. n8n records that outcome and never initiates pricing.

Local runtime: Tender API, Operations Console (`http://localhost:3001`), Mastra
Studio on port `4113`, credential-free n8n `1.112.6` intake, and a private S3
evidence archive outside the decision path.

## What this release is not

This is an independent engineering project inspired by public information about
business-energy tendering. It does **not** reproduce tem's internal tender
process, business policy, APIs, data model, pricing interfaces, or Rosso
architecture. All companies, brokers, sites, documents, meters, rules, and
tender records are synthetic.

Real pricing, real customer or broker data, hosted runtime, concurrent
database, production authentication, GitHub-to-AWS OIDC, outbound email/chat,
and PDF intake are out of scope.

## Demo coverage

Fresh setup uses synthetic data only. See the [README walkthrough](../../README.md#reviewer-walkthrough)
and [runbook](../runbook.md).

| Story | How to rehearse | Evidence |
| --- | --- | --- |
| Ready | `npm run demo:seed`; Console detail for the clean case | One mocked handoff on `tender-clean-001` only |
| Missing information | Same seed; missing-consumption case | `NEEDS_INFORMATION`; receipt `NOT_SENT`; no handoff |
| Human review | Same seed; conflicting-date case | `HUMAN_REVIEW`; review disposition does not change the route or create a handoff |
| Duplicate | n8n `clean.json` then `duplicate.json`, or API replay of an active `tenderId` with a new key | Second run `DUPLICATE`; no extra handoff |
| Visible failure and recovery | [Reliability rehearsal](../reliability-rehearsal.md) | Failure stays `FAILED`; no unsafe pricing; replay is idempotent |

Pending required documents stay `PROCESSING` without a route (n8n `pending.json`).
